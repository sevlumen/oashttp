# v2.0.1 Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the current typed `net/http` + OpenAPI scope, lock its key architecture boundaries, and publish the already-declared `v2.0.1` as a verified GitHub release.

**Architecture:** Keep the runtime/public API unchanged. Add a standard-library-only architecture regression test, align release metadata with the final source, and make publishing an explicit GitHub Actions path that can only release the exact `main` commit whose package version matches the requested tag.

**Tech Stack:** Go 1.22+, standard library only, GitHub Actions, GitHub CLI available on hosted runners.

## Global Constraints

- No new application feature such as CORS, OAuth/OIDC, rate limiting, logging, or request IDs in this completion change.
- No public API change.
- No version bump beyond the already-declared `2.0.1`.
- No third-party runtime dependency.
- Preserve OpenAPI golden output.
- Preserve Go 1.22 compatibility.
- Final source must pass the existing Go 1.22–1.26 matrix, race, coverage, golden, fuzz, benchmark, and `govulncheck` gates.
- Release publication must target the exact final `main` commit and must fail if `v2.0.1` already exists.

### Task 3: Harden and automate the release workflow

**Files:**
- Modify: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `publish/vX.Y.Z` branch names, `version.go`, exact `main` SHA.
- Produces: verified annotated tag `vX.Y.Z` and a GitHub Release for that tag.

- [ ] **Step 1: Preserve tag verification and update actions**

Keep tag verification for externally-created `v*` tags, but use:

```yaml
- uses: actions/checkout@v6
- uses: actions/setup-go@v7
```

The tag job must still verify `GITHUB_REF_NAME == v${Version}` and run `go vet`, `go test -race`, and benchmarks.

- [ ] **Step 2: Add the explicit publish branch trigger**

Configure the same workflow for:

```yaml
on:
  push:
    branches:
      - "publish/v*"
    tags:
      - "v*"
```

Set:

```yaml
permissions:
  contents: write
```

- [ ] **Step 3: Add a publish job guarded to publish branches**

The job must:

```bash
tag="${GITHUB_REF_NAME#publish/}"
package_version="$(sed -n 's/^const Version = "\([^"]*\)"/\1/p' version.go)"
test "$tag" = "v${package_version}"

git fetch origin main --depth=1
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"

if git ls-remote --exit-code --tags origin "refs/tags/${tag}" >/dev/null 2>&1; then
  echo "tag ${tag} already exists" >&2
  exit 1
fi
```

This makes publication fail closed if the requested release does not exactly match the final `main` source.

- [ ] **Step 4: Run release verification before publication**

The publish job must run the same repository quality gates needed for release confidence:

```bash
test -z "$(gofmt -l .)"
go vet ./...
go test ./... -shuffle=on -count=3
go test -race ./...
go test ./... -coverprofile=coverage.out
coverage="$(go tool cover -func=coverage.out | awk '/^total:/ {gsub(/%/, "", $3); print $3}')"
awk -v coverage="$coverage" 'BEGIN { if ((coverage + 0) < 70) exit 1 }'
UPDATE_GOLDEN=1 go test ./examples/users-api -run TestUsersAPIEndToEnd/openapi_golden -count=1
git diff --exit-code -- testdata/users.openapi.golden.json
go test ./internal/route -run=^$ -fuzz=FuzzRouteParserNeverPanics -fuzztime=15s
go test ./internal/binding -run=^$ -fuzz=FuzzCompiledBinderNeverPanics -fuzztime=15s
go test ./... -bench=. -run=^$ -benchtime=100ms
go install golang.org/x/vuln/cmd/govulncheck@v1.6.0
govulncheck ./...
```
