# v2.0.2 Foundation P0 Implementation Plan

> **For agentic workers:** This file records the approved plan and its execution status. Implementation was performed with the superpowers executing-plans and TDD workflows.

**Goal:** Remove validation/OpenAPI semantic drift, centralize HTTP response-body status semantics, and publish the correctness fixes as `v2.0.2` without changing the public API.

**Architecture:** `internal/validationrule` owns dependency-light parsing and normalized validation-rule semantics shared by runtime validation and schema generation. `internal/httpsem` owns dependency-light HTTP response-body status semantics shared by runtime result writing and operation/OpenAPI compilation.

**Constraints:** Go 1.22 minimum; standard-library runtime only; no public API redesign; no CORS/OAuth/OIDC/request-ID or other feature expansion; unaffected OpenAPI output must remain stable.

## Task 1 — Validation/schema RED contracts

- [x] Add schema regression coverage for map `min/max`, numeric `len`, and typed scalar `oneof`.
- [x] Add runtime validation coverage preserving supported scalar `oneof` behavior and rejecting non-scalar `oneof`.
- [x] Verify the test-only head fails for the intended pre-fix behavior.

**Evidence:** CI #198 on test-only head `a520a9310f362529ac7dfa55d623cbfb0653e95f` failed because map constraints were emitted as `minItems`/`maxItems` and non-scalar `oneof` was still accepted, while formatting/module/vet remained clean.
