# v2.0.2 Foundation P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove validation/OpenAPI semantic drift, centralize HTTP response-body status semantics, and publish the correctness fixes as `v2.0.2` without changing the public API.

**Architecture:** Introduce two dependency-light internal packages: `internal/validationrule` owns parsing and normalized validation-rule semantics, while `internal/httpsem` owns shared HTTP status/body protocol facts. Runtime validation and schema generation consume the same validation IR; runtime response writing and operation/OpenAPI compilation consume the same HTTP status helper.

**Tech Stack:** Go 1.22+, standard library only, GitHub Actions, GitHub CLI release workflow.

## Global Constraints

- Keep the public `github.com/sevlumen/oashttp/v2` API source-compatible.
- Keep Go 1.22 as the minimum supported Go version.
- Keep zero third-party runtime dependencies.
- Preserve existing runtime behavior except where the current behavior or generated schema is incorrect.
- Preserve existing OpenAPI output for unaffected operations.
- Do not add CORS, OAuth/OIDC, request IDs, rate limiting, logging, metrics, or other application features.
- Release the completed correctness fixes as patch version `v2.0.2` only after reviewed merge and green post-merge CI.

- Produces: type-correct JSON Schema/OpenAPI constraints matching runtime validation.

- [ ] **Step 1: Make schema tag application return errors**

Change field-tag application from silent best-effort parsing to deterministic error propagation when shared validation parsing or typed enum conversion fails.

- [ ] **Step 2: Map normalized rules by field kind**

Required mappings:

```text
string min/max/len       -> minLength/maxLength
slice,array min/max/len  -> minItems/maxItems
map min/max/len          -> minProperties/maxProperties
numeric min/max          -> minimum/maximum
numeric len=N            -> minimum=N, maximum=N
gte/lte                  -> minimum/maximum
email                     -> format=email
uuid                      -> format=uuid
oneof                     -> typed enum values
required                  -> parent object required list
```

- [ ] **Step 3: Convert `oneof` choices to scalar JSON values**

Use the base field type to parse booleans, signed/unsigned integers, and floats; strings remain strings. Invalid choices fail schema generation rather than producing misleading output.
