# v2.0.1 P0-P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an additive v2.0.1 candidate with corrected support policy, raw `http.Handler` integration, scoped middleware, operation metadata, and named security providers.

**Architecture:** Extend the existing operation definition/compiler instead of introducing a second router. Typed and raw operations share registration, OpenAPI metadata, security, context metadata, and middleware; only typed operations invoke binding/validation. Legacy bearer authentication is adapted into the new security-provider pipeline.

**Tech Stack:** Go 1.22+, standard `net/http`, existing internal OpenAPI 3.1 model, GitHub Actions CI.

## Global Constraints

- No third-party runtime dependencies.
- Preserve existing v2 public behavior and legacy bearer/OpenAPI defaults.
- New APIs are additive.
- OAuth2 flow/scopes remain out of scope for v2.0.1.
- Follow RED/GREEN testing for behavior changes.
